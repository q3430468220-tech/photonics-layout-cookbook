01 Why

What foundry-compatible means

A common way to simulate a device is to draw it inside the simulator and type the layer stack in by hand. When you design for a foundry, the process is fixed and the layout is what you deliver. The simulation then has to show what that layout becomes on that process.

The usual way

The structure is typed into each script

Every script draws the device again and repeats the stack: thicknesses, materials, doping. Nothing ties that structure to the layout you send to the foundry.

fdtd.addrect()
fdtd.set("name", "core")
fdtd.set("y span", 0.5e-6)
fdtd.set("z span", 0.22e-6)
fdtd.set("material", "Si (Silicon) - Palik")
# ... the slab, the oxide, the implants and the metals,
# and all of it again in the next script

typed by hand. An illustration, not a file of this course.

The foundry-compatible way

The structure is built from two files

The layout is drawn with the PDK, and a process file describes the stack once. Layer Builder turns the two into the 3D structure, in the same way for FDTD, MODE, CHARGE and HEAT. No simulation script contains a thickness, a material or a doping level.

app.addlayerbuilder()
app.loadgdsfile("devices/gds/ring_modulator.gds")
app.loadprocessfile("gsip_process_file_py/gsip_process.lbr")
# the stack, the materials and the doping
# come from the process file

the two files. As in lumerical_simulations/flow.py.

02 The flow

One layout, one process file

The course follows the design flow of a foundry PDK: four stages in a row and, underneath them, the PDK that feeds them. Here the PDK is a teaching process called GSiP, short for generic silicon photonics. It is written down twice, as a gdsfactory PDK for the layout and as a process file for the simulator, and tests check that the two agree.

04 The course

Five chapters, in order

The first chapters build one process twice, as a PDK for the layout and as a process file for the simulator. Chapter 4 simulates a ring modulator with them, and chapter 5 is about the day you hold a real foundry's manual.

Who it is for

Graduate students and engineers who design silicon photonic devices and want their simulations to show what a foundry will build. You should be able to read Python and have met waveguides and ring resonators before. You need no foundry PDK and no NDA: the teaching process is made of public values.

What you need

Python 3.12 or 3.13 and uv, for the layout, the design-rule check, the tests and every figure. Ansys Lumerical 2025 R1 with FDTD, MODE, CHARGE, HEAT and INTERCONNECT, for the simulations. The results are kept in the repository, so every chapter can be read without Lumerical.

How long it takes

About 3 hours of reading for the 5 chapters, and 80 minutes for the 5 device chapters. The seven simulation steps of the ring modulator take about 50 minutes of solver time on the author's machine.

  1. 01 The PDK Layers, stack, cross-sections and design rules, written as code. no Lumerical needed28 min
  2. 02 The device Drawing the ring modulator, then checking it with a design-rule check (DRC) and a connectivity check. no Lumerical needed28 min
  3. 03 The process file The same process as tables for the Layer Builder, and how to verify it. 27 min
  4. 04 The simulations Seven steps from the coupler to the circuit, with the pitfalls of each. 72 min
  5. 05 Your foundry Moving the flow to a real PDK without leaking NDA data. 27 min

06 Circuits

Devices become circuits

The devices of the library are put together into circuits, in four directions. The first is done: a 4 × 4 mesh of interferometers that holds any 4 × 4 unitary matrix. Its chapter lets you give it a matrix, read the sixteen heater voltages it needs, and send a vector of light through it, in your browser.

07 Start

Run it yourself

The layouts, the design-rule check and every figure run without Lumerical: the results are kept in the repository. You need Python 3.12 or 3.13 and uv. The simulations need Ansys Lumerical.

Read chapter 1 Open the repository
shell
# the layout and the tests
$ git clone https://github.com/q3430468220-tech/photonics-layout-cookbook.git
$ cd photonics-layout-cookbook
$ uv sync
$ uv run python devices/ring_modulator_builder.py
DRC passed: 0 errors, 0 warnings
$ uv run pytest

# redraw a figure from the kept results
$ uv run python lumerical_simulations/ring_modulator/figures/fig2_passive.py
