Chapter 2 drew the ring modulator. This chapter simulates it. The simulation is split into seven steps, and each step answers one question about the device with one solver. A step passes its result on to the next one, so that at the end the seven answers combine into the spectrum of a working modulator. The whole chain runs from one layout and one process file. No script contains a thickness, a material or a doping level.

Read the chapter in order. The later steps need results of the earlier ones (section 4.1 shows which), and their numbers are only meaningful once the earlier ones have been checked.

4.1 One pattern for every step #

Every step builds its structure in the same way:

small GDS drawn with the PDK   +   gsip_process.lbr   ->   Layer Builder object

The small GDS is a piece of the device, drawn with the layers of the PDK (chapter 1, docs/pdk.md). The file gsip_process.lbr is the process file (chapter 3). The Layer Builder reads both and makes the 3D structure that the solver meshes. The helper that does this is add_layer_builder in lumerical_simulations/flow.py, which the devices of the library share. The step scripts reach it through the common.py next to them. Its last two steps are:

python
    app.loadgdsfile(gds.as_posix())
    app.loadprocessfile(LBR.as_posix())

The consequence matters more than the code. A thickness, a material or a doping level is written once, in the process tables. If the process changes, the seven steps change with it, and the layout and the simulation cannot drift apart.

The flow is arranged after the flow chart of the Ansys and Tower Semiconductor workshop (see assets/design_flow.png). Its circuit-simulation stage is step 6 here. The compact-model stage is drawn but not built yet: steps 5 and 6 supply its numbers, and the circuit reads them from the result files.

The seven steps #

step folder solver script the question it answers what it passes on
0 0_layer_builder_check MODE (as an index probe) layer_builder_check.py Did the Layer Builder build the structure the layout describes? index maps of the finished device (figure 0 only)
1 1_coupling_coefficient FDTD coupling_coefficient_fdtd.py How much light crosses from the bus into the ring, for a given gap? κ²(gap) and its fit, to step 6
2 2_passive_mode_properties MODE (FDE) passive_mode_fde.py What does the bare ring waveguide guide: neff, ng, bend loss? neff, ng, bend loss, FSR, to steps 5 and 6
3 3_charge_profile CHARGE charge_profile.py How do carriers, capacitance and resistance change with reverse bias? carrier map to step 5; C, Rs, fRC to step 6
4 4_heat_profile HEAT heat_profile.py How many kelvin does one milliwatt of heater power add to the core? temperature map to step 5; K/mW, time constant
5 5_active_mode_properties MODE (FDE) active_mode_fde.py How do neff and loss change with bias and with heat? table of Δneff, loss and shift versus bias, to step 6
6 6_interconnect_ring_modulator INTERCONNECT ring_modulator_interconnect.py How does the ring behave as a circuit element: spectra, extinction, Q, bandwidth? the result of the chain: spectra and figures of merit

Data flow #

In words: step 5 needs the carriers of step 3, the temperature of step 4, and the bend orientation and group index of step 2. Step 6 needs the coupling of step 1, the waveguide of step 2, the loss and index change of step 5, and the bandwidth of step 3. Steps 0 to 4 read nothing from each other.

The figure is drawn from a table in figures/fig_data_flow.py, and a test compares that table with the folders the step scripts read. If a script starts to read another step, the test fails until the figure shows it.

4.2 Run it #

Prerequisites #

  1. Python 3.12 or 3.13, and uv. The environment is set up once from the repository root, as described in the root README.

  2. Ansys Lumerical 2025 R1 with the FDTD, MODE, CHARGE, HEAT and INTERCONNECT licences. The scripts reach it through lumapi, the Python API that ships with Lumerical.

  3. LUMERICAL_ROOT, the folder of the installation that contains api/python/lumapi.py. If it is not set, lumerical_env.py searches the usual install locations and uses the newest one. Set it explicitly if you have more than one version:

    $env:LUMERICAL_ROOT = "C:/Program Files/ANSYS Inc/v251/Lumerical"
    shell
    export LUMERICAL_ROOT=/opt/lumerical/v251

    Check it with uv run python lumerical_env.py. The command prints the installation and the path of lumapi.

  4. The layout devices/gds/ring_modulator.gds and the process file gsip_process_file_py/gsip_process.lbr. Both are kept in the repository, so the compiler of chapter 3 need not run again. If you change the device, run uv run python devices/ring_modulator_builder.py first.

Before any licence is used, run the tests. They need no Lumerical:

shell
uv run pytest

The 146 tests check the PDK, the layout, the design rules, the process tables, the device's nets and the figures redrawn from the kept data.

The commands, in order #

Run the scripts from the scripts folder. Each script writes into the folder of its step, using paths relative to its own location.

shell
cd lumerical_simulations/ring_modulator/scripts

uv run python layer_builder_check.py                 # step 0, about half a minute, MODE only
uv run python coupling_coefficient_fdtd.py --preview # optional: draw the FDTD window, no solver
uv run python coupling_coefficient_fdtd.py --dry     # optional: one gap, coarse mesh, a few minutes
uv run python coupling_coefficient_fdtd.py           # step 1, about 6 minutes per gap
uv run python coupling_coefficient_fdtd.py --summary-only  # optional: rebuild the table, no Lumerical
uv run python passive_mode_fde.py                    # step 2, about 7 minutes
uv run python charge_profile.py                      # step 3, about 9 minutes
uv run python heat_profile.py                        # step 4, about 3 minutes
uv run python active_mode_fde.py                     # step 5, about 1 minute
uv run python ring_modulator_interconnect.py         # step 6, under 1 minute

The order matters. Step 5 reads the files of steps 2, 3 and 4, and step 6 reads the files of steps 1, 2, 3 and 5. Steps 2, 3 and 4 do not depend on each other, and step 0 is only a check.

The run times are the ones measured on the author's machine, and they are rough guides. Step 1 takes about 6 minutes for each gap. The reference arm of step 1 is a fifth run and is not in the table, so budget about 30 minutes for the default run of step 1.

The --dry option of step 1 writes files named dry_* into the same folder. Delete them after the check. A dry run does not write the summary table.

4.6 Step 0. The Layer Builder check #

The question Does the Layer Builder make the structure that the layout describes?

The model. The whole device, devices/gds/ring_modulator.gds, is loaded with the process file into a Layer Builder object 36 µm wide. The mode solver is used only as a probe. It meshes a plane, and it reports the refractive index that it sees on every mesh point. Two vertical cuts and four horizontal cuts are taken:

  • a vertical cut through the PN section on the north side of the ring (x = 0, mesh 20 nm), from z = −5.5 µm to 3.6 µm. It reaches the substrate and the buried oxide below the slab, and it shows the contacts, metal 1, the heater and the metal 2 wire above;
  • a vertical cut through the coupler on the south side (mesh 10 nm), which shows the ring core and the bus core on the common slab, and the gap between them;
  • horizontal cuts at z = 45 nm (slab), 160 nm (core), 1.17 µm (metal 1 and heater) and 2.65 µm (metal 2), with a 50 nm mesh over a 32 µm window.

A wrong layer expression in the process file shows up here at once, as a missing or misplaced shape. No solver licence is used beyond MODE.

What the probe sees. At ten points of the finished structure the solver should see the material that the process table assigns to the layer there. The expected values are the ones of a known material at 1550 nm, and the result is written to structure.txt:

Things that go wrong

  • A shape is missing from a panel. The layer expression in gsip_process.lbr does not match the layer in the GDS. Check the process tables (chapter 3). Then rerun step 0, which takes about half a minute.
  • The script stops with "devices/gds/ring_modulator.gds is missing". Run uv run python devices/ring_modulator_builder.py from the repository root, then step 0 again.
  • The probe shows silicon where the heater should be. The Layer Builder is not centred on the origin of the GDS. The script sets "Centered at origin" for this reason: GDS coordinates equal simulation coordinates.

Try it Open devices/gds/ring_modulator.gds in KLayout with klayout_tech/tech.lyt, and compare the layout of metal 1 with panel e of figure 0. Both show the same disc, arc and heater landings.

4.7 Step 1. The coupling coefficient, by FDTD #

The question For a given gap, what fraction of the power in the bus crosses into the ring?

The model. Only the coupling region is simulated. The ring arc is kept for 35° on either side of the coupling point. Beyond that the arc bends back, so that it leaves the window parallel to the bus and all four ports are normal to x. Panel a of figure 1 below shows the window. The ports are:

port where what it is for
1 bus, left end the light enters here
2 bus, right end the light that stays in the bus
3 ring arm, left end input of the reference run of the arm alone
4 ring arm, right end the light that has crossed into the ring

Light enters at port 1. The transmission t² = |S21|² stays in the bus. The coupling κ² = |S41|² is the power that crosses into the ring. Two settings matter.

  • The reference arm. The arm itself loses light, through bend radiation and through the two curvature reversals. Without a correction the coupling would be too low. The script therefore runs a second simulation without the bus, sends light from port 3 to port 4, and measures the transmission of the whole arm, T = 0.9473. Light coupled from the bus passes only half of the arm, so the correction is κ² = |S41|² / √T. Half an arm transmits √0.9473 = 0.9733.
  • The mesh over the coupler. The gap sets the coupling, so the mesh is refined in the gap region to 20 nm. The slab covers the whole window, as it does in the device, where the slabs of ring and bus merge.

The simulation uses the process file through the Layer Builder, a mesh accuracy of 2, a simulation time of 2.5 ps with auto shutoff, and 101 frequency points from 1500 to 1600 nm.

The results (coupling_vs_gap.txt):

gap (µm) κ² t² = |S21|² κ² + t² raw |S41|² minutes
0.200 0.11817 0.88166 0.9998 0.11501 5.7
0.300 0.03687 0.96308 1.0000 0.03589 5.9
0.400 0.01129 0.98870 1.0000 0.01099 5.6
0.500 0.00344 0.99656 1.0000 0.00335 5.6

The fit is κ² = 1.26 · exp(−gap / 84.8 nm), for gaps of 200 to 500 nm. It is an interpolation formula. Do not extrapolate it: its amplitude 1.26 is above 1, which no physical coupler reaches. The result file also lists the reflections |S11|² and the crosstalk |S31|², both below 10⁻⁶, which are negligible.

The mesh check. The table is only as good as the mesh. One gap, 400 nm, was run three ways, and the raw |S41|² at 1550 nm was compared:

mesh over the coupler raw |S41|² change run time
20 nm (the default) 0.010989 reference 5.6 min
20 nm, mesh boxes cut at the silicon surfaces 0.010949 −0.4 % not timed
10 nm (--gap-mesh 0.01) 0.010774 −2.0 % 18.6 min

The change is small, but it is not zero. A 2 % change in κ² moves the gap of critical coupling by about 2 nm, and near critical coupling it changes the extinction by many decibels (step 6). So κ² is known to about 2 %. The tables of this folder are from the default mesh. Running all gaps with the fine mesh is the exercise of this step.

Reading the figure.

  • a, the field. Light comes in from the left on port 1, in the bus at the bottom. The bright band at the bottom is the bus mode. What it tells you. The coupling is set by the gap, exponentially. Changing the gap by 30 nm changes κ² by roughly 30 %. This is the most sensitive knob on the mask, and step 6 shows what it does to the extinction.

Check The energy balance κ² + t² = 1 holds to four digits at every gap (0.9998 to 1.0000). The coupler has no loss of its own in the model, so the 0.0002 deficit at 200 nm is a numerical residual.

Things that go wrong

  • The coupling is about 2.7 % too low. The reference run was skipped (--no-reference), so the arm loss was not divided out. Without the correction κ² is low by the factor √T = 0.9733, that is by 2.7 %. Run the default, which includes the reference.
  • The script stops with "the engine finished but the file holds no results". The solver ran but did not write the field data. Read the *_p0.log file of the failing run in the step folder.
  • The run through the job manager picks a GPU resource or fails without a message. This is why the default runs the CPU engine directly. Use --job-manager only if the job manager is configured for your machine.
  • The --dry numbers differ from the table. The dry run uses a coarse mesh and one gap. Its numbers are for checking the set-up, not for the table.

Try it Open the window before running anything. In scripts/coupling_coefficient_fdtd.py, change ARM_ANGLE from 35 to 45, then run uv run python coupling_coefficient_fdtd.py --preview. The picture figures/check_coupler_setup.png shows the wider arm and where the ports moved. This writes only the preview picture, not the step results.

4.8 Step 2. The passive waveguide, by MODE #

The question What does the bare rib waveguide of the ring guide: effective index neff, group index ng, the loss of a bend, and how many modes does it carry?

The model. A straight 6 µm piece of the rib cross-section is loaded into a Layer Builder. It has no implants and no contacts, so the silicon is plain silicon. The mode solver uses a window of 8 µm by 2.4 µm with perfectly matched layers on every side, and a uniform mesh of 20 nm. On top of that, every silicon surface of the rib carries a mesh line, with a 10 nm mesh over the rib. The section "The mesh, and why it decides the answer" below explains why this matters. The steps of the script are:

  1. the straight waveguide at 1.55 µm: neff, ng, mode profile;
  2. the same cross-section bent to the ring radius, 10 µm: neff, ng, radiation loss;
  3. the bend radius swept from 4 to 20 µm: radiation loss, and overlap with the straight mode;
  4. the wavelength swept from 1.50 to 1.60 µm: neff(λ), and ng from its slope;
  5. the core width swept from 0.30 to 0.80 µm: neff of TE0 and TE1.

The solver searches for the modes near the highest index, which also returns slab and boundary modes. The script keeps only the modes that are mostly TE (TE fraction above 0.5) and mostly inside the core (more than 30 % of the power in the core).

The results (rib_passive.txt):

quantity value
straight TE0, 1.55 µm neff = 2.56770, ng = 3.9370, TE fraction 0.987
ring, R = 10 µm neff = 2.57016, ng = 3.9361
mode shift of the bend, R = 10 µm 26 nm further out, away from the ring centre
overlap with the straight mode, R = 10 µm 0.9950
bend loss, R = 4 µm 15.2 dB/cm
bend loss, R = 5 µm 0.56 dB/cm
bend loss, R = 6 µm and above below the solver floor
ng from the slope of neff(λ), 1500 to 1600 nm 3.916 (0.5 % below the solver's value)
free spectral range, R = 10 µm λ² / (ng L) = 9.71 nm

Width sweep. At 0.40 µm and below the rib carries one TE mode. At 0.45 µm a second TE mode appears, but it lies below the fundamental mode of the 90 nm slab alone (neff 2.104), so it is not guided. At 0.50 µm the second mode, TE1, has neff = 2.115, about 0.01 above the slab mode, and it is guided. The design width of 0.5 µm is therefore close to the cut-off of the second mode.

Figure 2.

Reading the figure.

  • a, the straight mode. The mode sits over the core and leaks into the slab, as a rib mode does. The outline is the rib. The effective index 2.568 is the index the mode feels, between the 3.476 of silicon and the 1.444 of oxide.
  • b, the bent mode. The bend pushes the mode outwards, away from the ring centre. The orange dot is the centroid. The shift is 26 nm, and it is why the bend orientation matters in step 5.
  • c, dispersion. neff falls with wavelength. The slope gives the group index, ng = n − λ dn/dλ. The slope fit gives 3.916, the mode solver 3.937 for the straight waveguide at 1550 nm. The free spectral range of the ring, 9.7 nm, is λ² / (ng L) with the solver's value of ng for the bent waveguide, 3.936.
  • d, bend loss. Below 5 µm the bend radiates strongly: 15.2 dB/cm at 4 µm. The design radius of 10 µm is far in the region where the loss is below the solver's noise floor, shown as open circles on the grey band at 10⁻³ dB/cm.
  • e, width. TE0 rises steadily with width. TE1 appears at 450 nm, below the line of the slab mode, and is guided from 500 nm, where it lies 0.01 above that line. The grey line is the fundamental mode of the 90 nm slab, computed in the figure script from the slab equation. The design width of 500 nm lies above the threshold.

What it tells you. The ring waveguide is a good guide at 10 µm, with almost no bend loss and a free spectral range of 9.7 nm. The 0.5 µm rib carries a second TE mode, weakly confined. The modulator couples to TE0 only, so the second mode does not matter for the ring as drawn. A designer who widens the waveguide should expect the second mode from 0.5 µm upwards.

Check The group index from the wavelength slope, 3.916, agrees with the solver's value, 3.936, to 0.5 %. This is the independent check of ng. The analytic slab line in panel e checks the solver at the cut-off of TE1.

The rib waveguide chapter of the device library treats this cross-section by itself, and splits the loss of a bend into radiation and the mismatch at its two ends.

The mesh, and why it decides the answer #

This is the most instructive pitfall of the course. The effective index depends on the mesh of the mode solver, not only on the geometry, and the dependence is larger than the effect that the heater or the bias produce.

The solver does not place a mesh line on every interface. A uniform mesh of 20 nm has lines wherever the cell boundaries happen to fall. On the 90 nm slab surface and on the core sidewalls they fall at different places in different windows. So which interfaces carry a line depends on where the window starts.

The same undoped rib, bent to R = 10 µm, gives:

mesh window of step 2 (8 × 2.4 µm) window of step 5 (3.4 × 1.9 µm) difference
uniform 20 nm, no mesh lines on the interfaces 2.5765 2.5693 0.0072
uniform 10 nm 2.5710 2.5710 0
uniform 5 nm 2.5705 2.5705 0
20 nm, with a 10 nm override over the rib (used) 2.5702 2.5701 −2 × 10⁻⁵

A difference of 0.007 in neff is larger than the effect of 10 mW of heater power on the index (step 5). A simulation whose window had been placed differently would have given a different waveguide. The rule that follows is this: force a mesh line on every interface that matters, and check that two windows give the same answer.

The script does that in the function add_rib_mesh of lumerical_simulations/solvers.py. It adds two mesh overrides whose faces lie on the silicon surfaces: a core box of width W, from the top of the slab to the top of the core, and a slab box 0.3 µm wider on each side, from the bottom of the slab to its top. Inside the boxes the mesh is 10 nm. Every face of an override becomes a mesh line.

Two practical details matter:

  • The override is added last, after every property of the FDE object is set. A new object takes the selection in Lumerical. Adding the override right after addfde() makes the next set fail with "the requested property 'solver type' was not found".
  • The mesh is no longer uniform, so every sum over a field map is weighted by the area of its cells (np.gradient gives the cell widths). The overlap of the bent mode with the straight one is computed the same way.

The result is an absolute index good to about 5 × 10⁻⁴. Two windows with the same mesh give the same answer, which is the check. Steps 2 and 5 are compared directly in section 4.11.

The window and the mesh are not the only source of error. Lumerical interpolates the tabulated silicon index linearly between its sample wavelengths. The material dispersion is therefore piecewise constant, and the solver's ng changes in steps: it is 3.869 at 1530 nm and 3.941 at 1540 nm. The slope fit over 1500 to 1600 nm averages over these steps, which is why it differs by 0.5 % from the local value at 1550 nm. The steps are a feature of the material table, not a mode jump.

Things that go wrong

  • The bend loss is enormous, and the mode centroid moves towards the ring centre. The bend orientation is wrong. The script detects this from the sign of the centroid and turns the bend through 180°. If you change the layout so that the ring centre lies on the other side, check the line "bend orientation" in rib_passive.txt.
  • The "fundamental" mode is a slab or boundary mode. The solver returns every mode near the highest index. The filter keeps only TE modes with more than 30 % of their power in the core. The script also stops if the mode of the default waveguide is not TE or not in the core.
  • The wavelength sweep jumps between modes. The built-in sweep of the solver can jump to boundary modes. The script solves once per wavelength instead.
  • The waveguide looks single-mode, but it is not quite. The 0.5 µm rib is at the edge of the second mode. Read panel e before you quote single-mode operation.
  • Two windows give different absolute indices. The mesh has no line on an interface. Use the rib override of add_rib_mesh, and compare two windows before you compare absolute indices.

4.9 Step 3. The PN junction, by CHARGE #

The question When the junction is reverse biased, how do the carriers, the capacitance and the series resistance change, and how fast could the junction switch on its own?

The model. A straight piece of the rib cross-section with implants and contacts, rib_pn, is loaded into the Layer Builder. The doping comes entirely from the process file. The process file splits each contact via by the implant under it, so there are two separate solids: Via_contact_P (the anode, outside the ring) and Via_contact_N (the cathode, inside the ring). The bias is the anode voltage minus the cathode voltage, so reverse bias is negative. The simulation is a 2D cross-section, normalised to the length of the doped arc, 41.89 µm, so that currents, capacitance and resistance are those of the whole PN section.

The script does two things.

  1. A steady-state sweep from 0 V to −4 V in 17 points. It records the electron and hole densities for step 5, and it checks the doping against the process tables.
  2. A small-signal run at each bias, at four frequencies. The junction is a series RC: its impedance is Z = 1/Y = Rs − j/(ωC). The series resistance is Rs = Re Z, and the capacitance is C = −1/(ω Im Z). The capacitance is read at the lowest frequency (100 MHz) and the resistance at the highest (30 GHz). The intrinsic bandwidth is fRC = 1/(2π Rs C).

Settings that matter:

  • A fine mesh of 8 nm over the rib. The capacitance comes from how far the depletion edge moves per volt. With the automatic mesh alone, C(V) scatters by several per cent from run to run.
  • The simulation region must not be deleteall-ed. That would remove the materials group that the process file fills, so the script switches to the layout instead.
  • The small-signal analysis needs the Newton solver.
  • The formula C = Im(Y)/ω is right only when ωRsC is much less than 1. At 100 MHz and a few hundred ohms the error is small, but at the highest frequencies it is not. The series form is exact at every frequency, so the script uses it.

4.10 Step 4. The heater, by HEAT #

The question How many kelvin does one milliwatt of heater power add to the waveguide core, and how fast does the core warm up?

The model. A straight piece of the ring cross-section, drawn exactly as ring_modulator_builder draws it: the rib, the contact vias, metal 1 on both sides, and the TiN film above the core. The stack and the thermal material models come from the process file. Metal 1 and the vias are in the model on purpose. Aluminium next to the heater spreads its heat, and the vias lead it down into the slab. The inner disc of metal 1 is drawn from 1.6 µm to the ring centre. The simulation is a 2D cross-section normalised to the length of the heater filament, 44.72 µm, so the power you set is the total heater power.

The heat sink is a temperature boundary condition of 300 K on the solid Si_Substrate, and the simulation region includes that solid. The region must stay inside the layers of the process file. If it does not, the solver stops with the message "No thermal material properties defined for domain".

The script makes three runs.

  1. Steady state at several powers (2, 5, 10 and 20 mW by default). It records the temperature map at 10 mW for step 5, and the rise of the core and of the film against power. The energy balance is computed from the map of the 10 mW run (see below).
  2. The same without metal 1 and the vias. The difference is the cost of the electrodes.
  3. A transient run at the reference power of 10 mW. The power is switched on at 0.1 µs, and the core rise is recorded for 200 µs. The time constant and the rise time follow from the rise.

The heat source, and why it matters #

This is the pitfall of step 4, and it is worth telling in full, because the same mistake looks harmless. The Joule heat has to be generated in the film. The correct model is a uniform heat source assigned to the solid Heater. The heat is generated in the volume of the film, and the film conducts it to the core.

There are two wrong ways to write the same source, and each looks equivalent.

  • A thermal power boundary condition on the solid Heater. The core temperature comes out the same within 0.4 %. But the boundary condition cuts the film out of the thermal domain, so the film no longer conducts the heat. In that model the film is 23 K hotter in its middle than at its edges.
  • A heat source drawn as a box over the film. It also heats the mesh cells that it touches, so 12 % more power than requested arrives at the heat sink.

The check that finds the second error is an energy balance. The script integrates the heat flux that leaves through the buried oxide into the substrate, and compares the integral with the power that was set. A correct model sends out exactly the power that was put in. The reference run prints "energy balance: 10.00 mW reach the heat sink, 10.00 mW were set". A model with a wrong source fails this line before any number is used.

Things that go wrong

  • The film is hotter in the middle than at the edges, by about 23 K. The heat is a thermal power boundary condition on the solid. Use the uniform heat source on the solid, as the script does.

  • The script stops with "No thermal material properties defined for domain". The simulation region has left the layers of the process file. Keep it inside the layers of the stack, between the bottom of the substrate and the top of the oxide.

  • The electrodes seem to add nothing. They were left out. Metal 1 and the vias are part of the model on purpose. Without them the core rises 27 % more for the same power (2.98 against 2.35 K/mW).
  • The project file is about 15 times larger than it should be. The transient time steps are stored in the project. The script drops them after the run.

4.11 Step 5. The active waveguide, by MODE #

The question When the junction is biased, and when the heater is on, how do the effective index and the loss of the bent waveguide change?

The model. The silicon in the process file is an index-perturbation material. Its index responds to two things, once the simulation is given the map of each:

  • carriers, through the Soref-Bennett coefficients of Nedeljkovic, Soref and Mashanovich (2011);
  • temperature, through the linear coefficient dn/dT.

Both maps come from earlier steps, and each is attached to the Layer Builder as a grid attribute.

  • Electrical. The PN section of step 3 is loaded, and the grid attribute np Density is filled with the carriers that CHARGE exported. The mode solver then gives neff and loss for each bias.
  • Thermal. The heater section of step 4 is loaded, and the grid attribute temperature is filled with the temperature that HEAT exported. The solver gives neff at 10 mW of heater power.

The waveguide is solved bent to the ring radius, with the bend orientation that step 2 found. The mode moves outwards, towards the p side, so it sees each half of the junction in a different way. The mode window is 3.4 µm wide and 1.9 µm high, which keeps it inside the contact vias and below metal 1. The mesh is the one of step 2: 20 nm, with the 10 nm rib override of section 4.8.

Two baselines are used, and they are not the same.

  • The Δneff and the resonance shift are measured from 0 V, not from the undoped waveguide. The zero-bias state already carries the carriers of the doping. Read Δneff as the change that the reverse bias makes to a doped device.
  • The loss of the undoped waveguide, 0.0255 dB/cm, is the run with no carriers at all. At 0 V the loss is 13.3 dB/cm, almost all of it free-carrier absorption of the doping.

The check against step 2. The undoped rib, solved in this step's window, gives neff = 2.570135. The same rib bent to R = 10 µm in step 2's window gives 2.570159. Their difference, −2.3 × 10⁻⁵, is well inside the tolerance of 10⁻³ that the script enforces. The script stores this difference as base_minus_passive, and it prints a warning if the two windows disagree by more than 10⁻³.

The relation between the index change and the resonance shift is the one used for every ring:

ring shift = dn_eff × (fraction of the ring that is modulated) × lambda / n_g

For the junction the fraction is 41.89 / 62.83 = 0.667. For the heater it is 44.72 / 62.83 = 0.712.

The modulation efficiency is Vπ·L = |V| λ / (2 Δneff). It is the product of the voltage that shifts the phase by π and the length over which the shift acts. Here the length is the doped arc, so read it as V·cm per unit length of the doped section.

4.12 Step 6. The ring as a circuit element, by INTERCONNECT #

The question Put together, what does the ring do to light? What are the extinction, the quality factor, the bandwidth, and the tuning of the resonance with bias and heat?

The model. INTERCONNECT is a circuit simulator. The element Optical Ring Modulator describes the ring as an all-pass ring, with its coupling, length, group index, loss, and a table of its index change against voltage. The element is connected to an optical network analyser at the bus, and a DC source drives the junction through the modulation port. The inputs come from the steps before:

The effective index of the element at 0 V is the index of the undoped bent ring, plus the carrier change of the doped fraction only. The absolute resonance wavelength is only as good as the absolute index, and the index of step 2 is good to about 5 × 10⁻⁴. The results of this step are therefore differences: shifts, tuning rates, and Q and extinction at a given gap.

The scattering loss, 2.2 dB/cm, is not a simulation. The mode solver has no sidewall roughness, so the value comes from Baehr-Jones et al. The second is the one used for "one FSR needs ... mW". The absolute wavelength of the design resonance is only as good as the absolute index, so the spacing is the more robust of the two.

The bandwidth. Two bandwidths limit the modulator, and they are combined here.

  • The optical bandwidth, c/(λQ) = 6.2 GHz. This is the linewidth in frequency, 1/(2π τphoton), and the usual photon-lifetime estimate of the optical bandwidth. The exact small-signal response depends on the laser detuning. On resonance its pole lies at half this value.
  • The electrical bandwidth of the junction, fRC = 64 GHz at 0 V (step 3).

The −3 dB point of two cascaded first-order responses, (1 + (f/f₁)²)(1 + (f/f₂)²) = 2, is found from the quadratic in f² and is 6.1 GHz. It is not the simple root-sum-square of the two bandwidths, which would give 6.2 GHz. The optical bandwidth limits the speed. The junction is not the bottleneck.

The voltage tuning. The shift per volt, averaged from 0 V to the end of the sweep at −4 V, is 11.2 pm/V. Step 5 gives the same value over the same range. The shifts of the two steps agree within 0.1 pm at each bias.

Heater tuning. 5, 10 and 20 mW shift the resonance by 620, 1240 and 2482 pm, which is 124 pm/mW. One free spectral range of 9.73 nm needs 79 mW. Step 5 gives 123.6 pm/mW from neff. The circuit reads the resonance of a 52 001-point spectrum over 21 nm, and it places each heater resonance next to its predicted position. If no resonance lies within a quarter of the FSR of the prediction, the script stops with a message rather than reporting a wrong shift.

What it tells you. The ring modulator as designed has a 46 dB extinction at 0 V, a Q of 31 000 and an optical bandwidth of 6 GHz. It is limited by its photon lifetime, not by the junction. The extinction depends on the gap so steeply that the design has to be fixed on the mask. A modulator twice as fast needs about twice the linewidth, which means a smaller Q and a shallower notch.

Check Three checks support this step. The analytic all-pass ring of panel b reproduces the simulated spectra. The analytic extinction and Q curves of panels d and e pass through the simulated points. And the bandwidths combine in the way the cascade formula says: the combined bandwidth is 6.1 GHz, and the optical one dominates. The interface of the element was itself checked against the analytic ring. coupling coefficient 1 is the power coupling κ², loss is in dB per metre, and the third column of the measurement table is the imaginary part of the index.

Things that go wrong

  • The spectrum is wrong at the right gap. The coupling coefficient was entered as an amplitude, not as the power κ². Check that the gap of the critical coupling is 371 nm, as the script prints it.
  • The loss is 100 times too large or too small. The loss of the element is in dB per metre, not dB per centimetre. The script converts it.
  • The third column of the table is read as the loss. It is the imaginary part of the index, which the element converts. Passing the loss in that column gives a wrong result without a warning.
  • A property change has no effect. Properties can be changed only after switchtodesign(). The script calls it before each change.
  • The design gap seems arbitrary. It is the swept gap with the highest extinction. A different gap grid gives a different design gap. Use --gap to set it explicitly.
  • The script stops with "no resonance within a quarter FSR". The heater shift does not match the prediction of step 5. Read the message: it prints the predicted and the nearest resonance. Check the heater power and the span of the spectrum.
  • The resonance shift is about 1.5 times too large. The index change of the junction has not been scaled by the fraction of the ring that carries it. The script scales the table by 67 %.

4.14 What the numbers say #

  • The photon lifetime limits the speed, at about 6 GHz. The junction could in principle reach 64 GHz, and the heater is slower still. A faster modulator needs a lower Q, which means a smaller gap, at the cost of extinction.
  • Free carriers set the loss. Of the 0.069 dB lost per round trip, 0.056 dB is the free carriers of the doped arc. Less doping, or a shorter doped arc, would lower the loss and raise the Q, at the cost of the modulation.
  • The heater sets the operating point, and the junction modulates around it. Four volts of reverse bias is worth about a third of a milliwatt of heater power. This is the usual division of labour in a thermally tuned ring: the heater aligns the resonance with the laser once, and the junction moves it at speed.
  • The extinction is very sensitive to the gap. It is 46 dB at 370 nm and about 15 dB at 340 and at 400 nm. A real design sweeps the gap on the mask, and checks the extinction against the tolerance of the lithography.
  • Metal 1 and the vias cost 21 % of the heater efficiency. They are part of the electrical connection, and they take heat away from the core. A designer who removes them to save area should expect a more efficient heater and a harder electrical layout.
  • The mesh matters more than the window. A mesh line that misses a 90 nm slab surface moves the effective index by 0.007, which is more than 10 mW of heater power (4.4 × 10⁻³ in the heated section) or 4 V of bias (1.7 × 10⁻⁴).

4.15 Limits of the model #

These are simulation results. Nothing here has been compared with a fabricated device.

  • The process is a teaching process. Before a tape-out, every number comes from the foundry.
  • The assumptions are: vertical sidewalls; flat doping profiles, so an abrupt junction; a planar top oxide; aluminium for all vias and metals; and TiN thermal and electrical data taken from bulk values. Lumerical's CHARGE and HEAT database has no TiN, so the aluminium model is attached and four properties are overridden. The top surface is insulating in HEAT, so there is no convection and no radiation.
  • CHARGE and HEAT use straight 2D cross-sections. Only the mode solver bends the waveguide.
  • Optical absorption by the heater and the metals is not included. The mode-solver window ends below them, with 0.88 µm of oxide between the core and the heater.
  • The circuit model has no self-heating, no two-photon absorption, and no RF model of the pads and the wires. fRC is the intrinsic junction limit.
  • The waveguide loss of 2.2 dB/cm is a published value for a comparable process, not a simulation.
  • The absolute effective index is good to about 5 × 10⁻⁴, and κ² of the FDTD step to about 2 %. Near critical coupling this leaves the depth of the resonance open: a 1 % change of κ² moves the extinction from 46 dB to 40 dB or to 77 dB. The gap of critical coupling moves by about 2 nm.
  • The 0.5 µm rib is close to cut-off for the second TE mode. The bend loss of TE1 has not been simulated.

Check yourself #

  1. Step 1 gives κ² = |S41|² / √T, where T = 0.9473. Why is the square root there, and what happens to κ² if you skip the reference run?
  2. Step 4 gives the same core temperature for a thermal power boundary condition and for a volume source on the solid. What is wrong with the first, and which check shows it?
  3. Step 2 gives the same effective index for the same rib in two different windows, once the mesh has lines on the silicon surfaces. Why did the uniform 20 nm mesh give a different answer in each window?
  4. The optical bandwidth is 6.2 GHz and the junction bandwidth is 64 GHz. Which one limits the speed, and what would you change to make the modulator faster?
  5. Step 5 gives 16.1 pm/V over the first 0.5 V and 11.2 pm/V over 0 to 4 V. Why are the two slopes different, and which one should a designer quote?
Answers
  1. The arm loses light, and only half of the arm lies between the bus and port 4, so the coupled light has crossed half an arm. Dividing by √T removes that loss. Without the reference, κ² is low by the factor 0.9733, that is by 2.7 %.
  2. The thermal boundary condition cuts the film out of the thermal domain. The film then does not conduct the heat, and its middle runs about 23 K hotter than its edges. The check is the energy balance: the heat that reaches the substrate must equal the power set.
  3. A uniform mesh has no line on the slab surface or on the core sidewalls, and which interfaces get a line depends on where the window starts. The mesh error (0.007) is larger than the physical effect of the bias. With a mesh line on every interface, the two windows agree to 2 × 10⁻⁵.
  4. The optical bandwidth limits the speed. A faster modulator needs a lower Q, which means a smaller gap, at the cost of extinction.
  5. The index change per volt falls with bias, so a slope over a short window near 0 V is steeper than one over the whole range. Quote both, each with its voltage range, because they answer different questions.
